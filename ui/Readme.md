# UI-слой: логика построения архитектуры

## Иерархия

- Верхняя иерархия — тесты (`ui/tests/`). Из тестов вызываются **степы страницы**, которые наследуются от `CommonSteps` (`ui/steps/common.steps.ts`).
- `CommonSteps` содержит степы компонентов, встречающихся на **всех** страницах (навигация, модалка регистрации, cookie-баннер), и общие методы: `navigateToPage()`, `checkCurrentUrl()`.
- Если компонент есть на **2 и более страницах, но не на всех** — степы компонента подключаются точечно в степах нужных страниц.
- Если компонент есть **только на этой странице** — степы страницы работают напрямую с Page Object этой страницы.
- В Page Object (`ui/pages/`) и Component Object (`ui/components/`) описываются **только селекторы и простые методы**: получить элемент/текст, клик (`select*`), заполнение (`typeTextIn*`), ожидание. Никаких ассертов и `test.step` — это территория степов.

## Правила, проверенные на практике

- **Локаторы — по `data-qa`.** Тексты на hh-платформе содержат неразрывные пробелы (`&nbsp;`), поэтому текстовые локаторы ненадёжны; `getByRole`/`getByText` — только для стабильной семантики. XPath — последний резорт.
- **Нормализация текста** (`replace(/(&nbsp;|\s+)/g, " ")`) — в PO, чтобы степы получали чистые строки.
- **Тяжёлые страницы** (вакансии): навигация с `waitUntil: "domcontentloaded"` — событие `"load"` может не наступить из-за сторонних скриптов.
- **Cookie-баннер** закрывается в `beforeEach` каждого спека: `mainPageSteps.cookieBannerSteps.acceptCookiesPolicyIfVisible()` — баннер перехватывает клики.
- **JS-шум** (фингерпринт-скрипты `chrome-extension://`) глушится `test.use({ jsErrorAllowlist: [...] })` с комментарием-обоснованием, а не `failOnJSError: false`.
- **Контентные блоки** проверяются aria-снапшотами: снапшот-данные в `ui/data/snapshots/` (`blocks.ts`, `searchResultBlocks.ts`), ключ блока — в типах `BlockName`/`PageBlocks` PO.

Подробные конвенции с примерами — скилл `.agents/skills/write-autotests/` (`references/ui/*`).
