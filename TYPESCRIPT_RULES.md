# 20 рулов для TypeScript-проекта

Сформулированы по опыту этого репозитория (Playwright-фреймворк, TS 6 strict, ESLint 10): каждое правило либо уже работает здесь, либо родилось из конкретного кейса. Три слоя исполнения: **компилятор** (tsc — не отключать), **линтер** (eslint — автопроверка), **конвенция** (AGENTS.md/скилл — ревью и привычка).

Легенда: ✅ — уже включено/соблюдается в этом проекте · 💡 — рекомендую добавить.

## A. Компилятор: нерушимый фундамент

### 1. `strict: true` — и никаких точечных ослаблений ✅
Не отключать флаги strict ради «неудобной» ошибки; уходить в `unknown` + сужение, а не в `//@ts-ignore`. Ошибка компилятора — контракт, а не помеха.

### 2. `exactOptionalPropertyTypes: true` ✅
`title?: string` ≠ `title: string | undefined`. Опциональное поле нельзя присвоить `undefined` — только не присваивать вовсе.
**Кейс проекта:** включали отдельным этапом (stage 6.3) — сломанные места сразу показали, где опциональность подменялась undefined-присваиванием.

### 3. `verbatimModuleSyntax: true` ✅
Типы и значения импортируются по-разному и явно. Отсюда правило 16 (import type) — это не вкус, а требование компилятора.

### 4. `noUncheckedIndexedAccess: true` ✅
Доступ по индексу/ключу возвращает `T | undefined` — компилятор заставляет проверить. Один из самых «неудобных» и самых полезных флагов.

### 5. `noPropertyAccessFromIndexSignature: true` ✅
Поля индекс-подписей — только скобками: `post["userId"]`, не `post.userId`.
**Кейс проекта:** именно поэтому билдеры (`postRequestBuilder`) пишут присваивания в скобках — не стиль, а флаг.

### 6. Гигиена-пакет ✅
`noUnusedLocals` + `noUnusedParameters` + `noImplicitReturns` + `noFallthroughCasesInSwitch` + `noImplicitOverride` + `useUnknownInCatchVariables` (+ `noConsole` в линтере). Мёртвый код и забытые ветки не живут дольше одного прогона tsc.

## B. Типы и границы данных

### 7. Никакого `any` — вход в систему через `unknown` ✅
`@typescript-eslint/no-explicit-any` с `fixToUnknown`. `any` отключает проверку дальше по цепочке; `unknown` требует доказать тип.
**Кейс проекта:** пробный файл-нарушитель одним `any` дал и `no-unsafe-return` в придачу — правило работает связкой.

### 8. Внешние данные валидируются на границе ✅
Ответы API/окружение/JSON проходят схему (у нас — Zod `z.strictObject`) до использования. Типы описывают «что должно быть», схемы — «что пришло».
**Кейс проекта:** strictObject ловит «протечку» лишних полей от провайдера — это осознанный контракт, не ослаблять до `z.object`.

### 9. Branded-типы для идентификаторов ✅
`PostId(1)`, `UserId(2)` — бренд защищает от перепутанных аргументов (`deleteAlbum(albumId)` с userId компилировался бы без него).
**Защита в два слоя** (задокументировано в скилле): бренд на этапе компиляции не даёт перепутать аргументы, а конструктор в рантайме отбрасывает мусорные значения — `assertPositiveIntId` требует целое число ≥ 1.

### 10. `satisfies` вместо проверочного `as` 💡
`satisfies Config` проверяет совместимость, сохраняя выведенный тип; `as` — вера без доказательства. В этом проекте применимо к конфигам, URLS-билдерам, таблицам сценариев.

### 11. Касты — только с обоснованием ✅
Прямой `as` — когда типы пересекаются. Двойной `as unknown as T` — только с комментарием «почему это осознанно».
**Кейс проекта:** `build()` билдеров врёт типом ради негативных payload'ов — и это задокументировано в комментарии к классу, а не спрятано.

### 12. Коды и статусы — enum/union, не литералы ✅
`HttpStatusCode.OK`, а не `200`. Магические значения запрещены AGENTS.md; единый enum даёт исчерпываемость и автодополнение.

## C. Промисы и async

### 13. Каждый промис обработан: `await` / `void` / `.catch` ✅
`no-floating-promises`. Fire-and-forget — только явным `void` с пониманием, что ошибка потеряна.
**Кейс проекта:** скилл `review-changes` тестируемым артефактом поймал `forEach(async …)` — классический будущий баг.

### 14. `async` не передаётся туда, где ждут sync ✅
`no-misused-promises` — ловит async-колбэки в sync API (listeners, sync-хуки). Причина большинства «почему мой try/catch не поймал».

### 15. Мёртвого `async` не бывает ✅
`require-await` + `await-thenable` (warn/error связкой).
**Кейс проекта:** правило сразу нашло `async`-колбэк в `test.step` без единого `await` — синхронный assert маскировался под асинхронный.

## D. Модули и импорты

### 16. `import type` для чистых типов ✅
`consistent-type-imports` (prefer: type-imports).
**Кейс проекта:** правило нашло `UserRole` и `z` из zod, импортированные как значения без нужды — runtime-импорт тянет модуль зря.

### 17. Порядок импортов — машине, модули — узкие ✅
`import-x/order` с pathGroups под алиасы (`@@/api/...`), расстановка только через `lint:fix`. Barrel-файлы (`index.ts`-реэкспорты) не плодить без нужды.
**Кейс проекта:** mega-баррель `api/types/common/index.ts` удалён при рефакторинге «focused modules» — узкие модули дают точечные import type и быстрый tsc.

## E. Паттерны и конвенции

### 18. Исчерпывающий switch через `never` ✅
```ts
default: {
  const _exhaustive: never = role;
  throw new Error(`Unknown: ${_exhaustive}`);
}
```
Добавил вариант в enum — компилятор сам покажет каждый незакрытый switch.
**Кейс проекта:** `getAuthHeaders` в headerUtils — эталонный образец.

### 19. Окружение читается лениво ✅
`requireEnv` вызывается в момент использования, не на import. Иначе запуск `--project=ui` требует все переменные всех проектов.
**Кейс проекта:** headerUtils документирует это в комментарии — без ленивости один пропавший `API_KEY` ронял бы unrelated-прогоны.

### 20. DI-поля классов: присваивание в конструкторе, не field-initializer ✅
```ts
private readonly submit: Locator;          // объявление
constructor(private readonly page: Page) { // 
  this.submit = this.page.getByRole(...);  // присваивание в теле
}
```
При `useDefineForClassFields`-семантике (target ESNext) initializer читает `this.page` до присваивания — TypeError в рантайме, линт не ловит.
**Кейс проекта:** главный gotcha апгрейда Playwright 1.65; запрет зафиксирован в AGENTS.md и скилле.

## Что бы я добавил из 💡

Минимальная добавка — **правило 10 (`satisfies`)**: конвенция в ревью + одна строка в AGENTS.md. Флаги компилятора у вас уже образцовые — их ценность в другом: **не отключать точечно**.
